# Hollow Watch bug hunt — 24 October 2026

This pass checked save migration, the new-player opening, home access, island raids, freight, combat transitions and build consistency. The existing checks initially passed, but eight additional reproduction tests failed before the fixes.

| Problem | Result after the fix |
| --- | --- |
| Returning through the city planner opened the cottage without recording the home visit. Players could remain stuck in the peaceful opening. | Every successful return to the city home records the visit and completes the short tip. |
| Entering an interior during a land fight could hide the encounter while its clock remained active. | Interior visits are blocked during combat and incompatible travel states. |
| Casino entry bypassed the naval battle/rescue restrictions used by other interiors. | Casino entry shares the same entry restrictions as other buildings. |
| The raid chart only recognised the original southern harbour. | Raids can depart from Thimblehaven, owned wharves, and remote island landings, and return to the correct local water approach. |
| Disabled ships could sail raids without repairs. | Raid selection excludes disabled hulls and explains when no seaworthy ship is available. |
| A ship on a freight trip could simultaneously be selected for a raid. | Reserved ships are excluded; another eligible ship can still sail. |
| Disabled hulls could run freight and earn money. | Freight dispatch requires a usable hull before charging money or creating a trip. |
| Migration restored the starter deed after validating the home, so a missing deed could erase the building. | The starter deed is restored before city validation; missing starter homes are also recovered, preserving cottage upgrades. |
| The port identified as the capital was named Tideham in travel UI. | It now consistently reads Port Victoria public harbour. |
| An unused route imported a router package absent from the standalone game. | The obsolete router wrapper is removed; TypeScript checks pass without installing an unused runtime. |

## Verification

- `npm run check:consistency` covers the reproductions plus normal visits, available replacement ships, home recovery and local raid return points.
- The city save tests still verify cargo, cart distance, stock and payment preservation. They now explicitly expect recovery of the missing starter home.
- All gameplay check scripts and `npm run check:types` were run after the fixes.
- A mobile-size browser check follows New game → skip arrival → starter loan → explore without the tip → Deeds → Your city → Return to your city home. It verifies that the home visit persists, the quiet opening remains intact, and the game resumes after reloading.
- The Android build is signed with the existing test key and increments the app version to 0.1.6 (version code 7). APK signature, asset contents and update compatibility are checked separately.

The browser checks do not establish native phone performance or every possible playthrough. No physical Android device was available for this pass.
